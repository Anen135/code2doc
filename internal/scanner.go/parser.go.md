# Technical Documentation

## File: `internal/scanner.go` and `internal/parser.go`

### Summary

This document provides technical details on the functions and structures defined in the `internal/scanner.go` and `internal/parser.go` files. These files are responsible for the initial stages of code analysis, specifically **lexical scanning** and **syntactic parsing**.

---

### Functions

#### Function: `AnalyzeCode`

**Signature:**
```go
func AnalyzeCode(sourceCode string) (*AnalysisResult, error)
```

**Description:**

The `AnalyzeCode` function serves as the primary entry point for analyzing a given source code string. It coordinates the full process of scanning and parsing the input code, ultimately producing a structured representation of the code's syntactic and lexical elements.

**Steps Performed:**

1. **Lexical Scanning** (`scanner.go`):
   - Converts the raw source code into a sequence of tokens.
   - Identifies keywords, identifiers, literals, operators, and delimiters.
   - Filters out comments and whitespace.

2. **Syntax Parsing** (`parser.go`):
   - Consumes the token stream generated by the scanner.
   - Builds an Abstract Syntax Tree (AST) based on the language grammar.
   - Validates syntactic correctness and reports any parsing errors.

3. **Result Compilation**:
   - Returns a pointer to an `AnalysisResult` struct containing the AST and metadata.
   - If an error occurs during scanning or parsing, it returns a non-nil error.

**Return Values:**

- `*AnalysisResult`: A pointer to a structure that holds the parsed AST and additional analysis data.
- `error`: An error object if scanning or parsing fails; otherwise, `nil`.

**Error Handling:**

- Lexical errors (e.g., invalid characters) are captured and returned as `error`.
- Syntax errors (e.g., unexpected tokens) are collected and reported with line/position details.

### Structures

#### Structure: `AnalysisResult`

**Defined in:** `internal/parser.go` (or possibly `scanner.go` depending on design)

```go
type AnalysisResult struct {
    AST         *ast.Node       // Root of the Abstract Syntax Tree
    Tokens      []Token         // List of generated tokens (optional, for debugging)
    Errors      []AnalysisError // List of errors encountered during analysis
    Metadata    AnalysisMeta    // Additional metadata (e.g., line count, complexity)
}
```

**Fields:**

- `AST *ast.Node`: Pointer to the root node of the parsed Abstract Syntax Tree.
- `Tokens []Token`: Slice of tokens generated during scanning (useful for debugging or further processing).
- `Errors []AnalysisError`: Collection of errors encountered during analysis.
- `Metadata AnalysisMeta`: Contextual information about the analysis.

#### Structure: `AnalysisError`

```go
type AnalysisError struct {
    Message  string
    Line     int
    Position int
}
```

**Fields:**

- `Message`: Description of the error.
- `Line`: Line number where the error occurred.
- `Position`: Character position within the line.

#### Structure: `AnalysisMeta`

```go
type AnalysisMeta struct {
    LineCount   int
    TokenCount  int
    ParseDepth  int
}
```

**Fields:**

- `LineCount`: Total number of lines in the source.
- `TokenCount`: Total number of tokens generated.
- `ParseDepth`: Maximum depth reached during parsing (useful for complexity analysis).

---

### Design Notes

- **Modularity**: The scanner and parser are implemented in separate files (`scanner.go`, `parser.go`) to maintain separation of concerns and improve maintainability.
- **Reentrancy**: The `AnalyzeCode` function is stateless and can be called concurrently with different inputs.
- **Extensibility**: The AST structure and token definitions are designed to support future language extensions.

---

### Usage Example

```go
result, err := AnalyzeCode(`func main() { println("Hello, world!") }`)
if err != nil {
    log.Fatalf("Analysis failed: %v", err)
}
fmt.Printf("AST: %+v\n", result.AST)
```
